# Как передать и запустить EcoWorld с самого начала

Ниже описан весь процесс: сначала разработчик предоставляет заказчику доступ к
GitHub, затем заказчик устанавливает Git, Node.js и PostgreSQL, скачивает проект
и запускает его.

## Часть 1. Что делает разработчик

### Шаг 1. Загрузить последнюю версию проекта на GitHub

Откройте PowerShell в папке проекта, где находится `package.json`, и выполните:

```powershell
git status
git add .
git commit -m "Подготовка проекта к передаче заказчику"
git push origin main
```

Если рабочая ветка называется не `main`, узнать её название можно командой:

```powershell
git branch --show-current
```

Затем вместо `main` необходимо указать полученное название ветки.

Адрес репозитория проекта:

```text
https://github.com/Adil78124/EcoWord
```

Файлы `.env`, `node_modules` и `.next` не должны загружаться в GitHub.

### Шаг 2. Добавить заказчика в GitHub

1. Заказчик создаёт аккаунт на [github.com](https://github.com).
2. Заказчик сообщает разработчику свой GitHub username.
3. Разработчик открывает репозиторий EcoWord на GitHub.
4. Открывает `Settings`.
5. Переходит в `Collaborators` или `Collaborators and teams`.
6. Нажимает `Add people`.
7. Вводит username заказчика и отправляет приглашение.
8. Заказчик открывает email или GitHub и принимает приглашение.

После этого заказчик сможет скачать проект и получать обновления.

Если проект нужно полностью передать заказчику, после проверки можно открыть:

```text
Settings -> General -> Danger Zone -> Transfer ownership
```

Затем указать GitHub username заказчика. После передачи владельцем репозитория
станет заказчик.

## Часть 2. Что устанавливает заказчик

Все следующие действия выполняются на компьютере заказчика.

### Шаг 1. Установить Git

1. Скачать Git с [git-scm.com/download/win](https://git-scm.com/download/win).
2. Запустить установщик.
3. Во время установки можно оставить стандартные настройки.
4. После установки перезапустить PowerShell или компьютер.

Проверить установку:

```powershell
git --version
```

Должен появиться номер версии Git.

### Шаг 2. Установить Node.js

1. Открыть [nodejs.org](https://nodejs.org).
2. Скачать версию **Node.js 20 LTS** или более новую LTS.
3. Запустить установщик.
4. Оставить включённым пункт установки `npm`.
5. После установки закрыть и заново открыть PowerShell.

Проверить установку:

```powershell
node --version
npm --version
```

Обе команды должны вывести номера версий.

### Шаг 3. Установить PostgreSQL

1. Скачать PostgreSQL с
   [postgresql.org/download/windows](https://www.postgresql.org/download/windows/).
2. Запустить установщик.
3. Оставить выбранными PostgreSQL Server и pgAdmin 4.
4. Во время установки придумать пароль пользователя `postgres`.
5. Обязательно сохранить этот пароль.
6. Стандартный порт оставить `5432`.

После установки открыть **pgAdmin 4** и создать базу:

1. Открыть `Servers -> PostgreSQL`.
2. Ввести сохранённый пароль.
3. Нажать правой кнопкой на `Databases`.
4. Выбрать `Create -> Database`.
5. В поле имени написать `ecoworld`.
6. Нажать `Save`.

## Часть 3. Скачать проект с GitHub

Открыть PowerShell и перейти, например, на рабочий стол:

```powershell
cd $HOME\Desktop
```

Скачать проект:

```powershell
git clone https://github.com/Adil78124/EcoWord.git
```

Если репозиторий приватный, GitHub попросит войти в аккаунт. Необходимо
использовать аккаунт, которому разработчик выдал доступ.

Перейти в папку проекта:

```powershell
cd EcoWord
```

Проверить наличие файла `package.json`:

```powershell
Get-ChildItem package.json
```

## Часть 4. Установить библиотеки проекта

В папке `EcoWord` выполнить:

```powershell
npm install
```

Команда скачает Next.js, Prisma и остальные библиотеки. В проекте появится
папка `node_modules`.

## Часть 5. Настроить файл `.env`

Создать `.env` на основе примера:

```powershell
Copy-Item .env.example .env
```

Открыть `.env` в Блокноте:

```powershell
notepad .env
```

Пример содержимого:

```env
DATABASE_URL="postgresql://postgres:ПАРОЛЬ@localhost:5432/ecoworld"
NEXT_PUBLIC_APP_URL="http://localhost:3000"
JWT_SECRET="ДЛИННЫЙ_СЛУЧАЙНЫЙ_СЕКРЕТ"
ADMIN_PANEL_ENABLED=true
```

Вместо `ПАРОЛЬ` указать пароль PostgreSQL, созданный при установке.

Для создания `JWT_SECRET` выполнить в отдельном окне PowerShell:

```powershell
node -e "console.log(require('crypto').randomBytes(48).toString('base64'))"
```

Полученную строку вставить в `.env` после `JWT_SECRET=`.

Если пароль PostgreSQL содержит символы `@`, `:`, `/`, `#` или `%`, их нужно
закодировать для URL. Проще при первом локальном запуске использовать сложный
пароль из букв и цифр.

Файл `.env` нельзя отправлять в GitHub, потому что он содержит пароли.

## Часть 6. Подготовить базу данных

В PowerShell, находясь в папке проекта, выполнить:

```powershell
npx prisma generate
npx prisma migrate deploy
```

Эти команды подключат Prisma и создадут необходимые таблицы в базе `ecoworld`.

Если появилась ошибка подключения, проверить:

- запущен ли PostgreSQL;
- правильно ли указан пароль в `DATABASE_URL`;
- существует ли база `ecoworld`;
- используется ли порт `5432`.

## Часть 7. Запустить сайт

Выполнить:

```powershell
npm run dev
```

После появления сообщения о готовности открыть:

```text
http://localhost:3000
```

Административная панель:

```text
http://localhost:3000/admin
```

Не закрывайте PowerShell во время работы сайта. Для остановки сервера нажмите:

```text
Ctrl + C
```

## Часть 8. Как запускать сайт в следующий раз

Повторно устанавливать Git, Node.js, PostgreSQL и библиотеки не нужно.

Открыть PowerShell и выполнить:

```powershell
cd $HOME\Desktop\EcoWord
npm run dev
```

Затем открыть [http://localhost:3000](http://localhost:3000).

## Часть 9. Как заказчику получить обновления

Когда разработчик загрузил изменения в GitHub, заказчик выполняет:

```powershell
cd $HOME\Desktop\EcoWord
git pull origin main
npm install
npx prisma migrate deploy
npm run dev
```

`npm install` и миграции рекомендуется выполнять после каждого обновления:
в новой версии могли измениться библиотеки или структура базы.

## Часть 10. Проверка production-сборки

Перед публикацией проверить, что проект собирается:

```powershell
npm run lint
npm run build
```

Для запуска готовой production-сборки:

```powershell
npm start
```

После этого сайт также будет доступен по адресу
[http://localhost:3000](http://localhost:3000).

## Важно перед публикацией сайта

В проекте сейчас присутствует временный фиксированный вход администратора в
`lib/auth/bootstrap-admin.ts`. Он предназначен только для разработки.

Перед публикацией необходимо:

1. Создать настоящего администратора в PostgreSQL.
2. Удалить временный пароль из исходного кода.
3. Сгенерировать новый `JWT_SECRET`.
4. Настроить production-базу PostgreSQL.
5. Добавить переменные окружения в Vercel.
6. Не загружать `.env` в GitHub.

Локальный запуск на компьютере и публикация сайта в интернете — это разные
этапы. Для размещения сайта в интернете дополнительно настраиваются Vercel,
облачная PostgreSQL-база и домен.
